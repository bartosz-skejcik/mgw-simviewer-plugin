<verified_tiles_api>
Verified against GLPI `11.0/bugfixes` (`src/Glpi/Helpdesk/Tile/`) via GitHub on 2026-07-21. Do NOT re-research — use these findings. Production runs GLPI 11.0.4; confirm only the flagged illustration value at deploy.

- Manager: `Glpi\Helpdesk\Tile\TilesManager`, singleton via `TilesManager::getInstance()`.
- Tile type: `Glpi\Helpdesk\Tile\ExternalPageTile` (correct choice for a plugin legacy front controller; `GlpiPageTile` is core-pages-only per CONTEXT decision).
- Add: `addTile(CommonDBTM&LinkableToTilesInterface $item, string $tile_class, array $params): int`. Body creates the tile via `$tile->add($params + ['_itemtype_item' => $item::class, '_items_id_item' => $item->getID()])` and returns the `Item_Tile` id. The profile→tile association is created inside `add()` through the `_itemtype_item` / `_items_id_item` magic keys — do NOT insert `Item_Tile` rows by hand.
- `ExternalPageTile` DB fields: `title`, `description`, `illustration`, `url` (table `glpi_externalpagetiles`; getters `getTitle()`, `getDescription()`, `getIllustration()` [falls back to `IllustrationManager::DEFAULT_ILLUSTRATION`], `getTileUrl()`). So `$params = ['title' => ..., 'description' => ..., 'illustration' => ..., 'url' => ...]`.
- Read existing: `getTilesForItem(CommonDBTM&LinkableToTilesInterface $item): array` — use for idempotency (compare each returned ExternalPageTile's `getTileUrl()` to the target url).
- Delete: `deleteTile(CommonDBTM&TileInterface $tile): void` — deletes both the `Item_Tile` link and the tile.
- Linkable holder: core `\Profile` `implements LinkableToTilesInterface` (confirmed in `src/Profile.php`). Pass core `\Profile` objects (NOT the plugin's `GlpiPlugin\Simviewer\Profile` subclass) to `addTile`.
- Link table (`Item_Tile`): `glpi_items_tiles`, columns `itemtype_item`, `items_id_item`, `itemtype_tile`, `items_id_tile` (+ `id`, `ranking`).

FLAGGED for deploy verification (Claude's Discretion per CONTEXT): the `illustration` field expects a GLPI illustration identifier (named SVG), NOT a Tabler `ti-` icon class. `ti ti-device-sim` stays the menu-entry icon (unchanged) but is likely NOT a valid tile illustration. If no confident illustration id is known, OMIT `illustration` from `$params` so `ExternalPageTile` uses `IllustrationManager::DEFAULT_ILLUSTRATION`; the tile still renders. Surface this choice in the SUMMARY for UAT.
</verified_tiles_api>
