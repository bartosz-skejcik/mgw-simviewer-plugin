# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** This phase's only UI surface is one native GLPI 11 helpdesk home-page tile (`ExternalPageTile`, system Tiles) registered at install time. GLPI core renders the tile's markup, spacing, typography, and color entirely — the plugin only supplies **data**: title, description, icon, and target URL (all in PHP, `plugin_simviewer_install()`). This phase also **removes** the plugin's only custom-styled/scripted surface (`public/js/nav-inject.js`, `ADD_JAVASCRIPT`/`ADD_HEADER_TAG` hooks). There is no custom CSS, no custom Twig template, and no client-side JS introduced by this phase. Consequently most template sections below are marked **not applicable — GLPI-native** rather than populated with invented tokens; inventing spacing/color/typography values here would create a false contract the executor could not (and must not) honor.

## Copywriting Contract

The tile has exactly one interactive affordance (the tile itself, click-through to `front/simcard.php`) and two data fields the plugin controls: title and description. Both must exist in `pl_PL` and `en_GB` (locale files `locales/pl_PL.po`, `locales/en_GB.po`), matching the project's existing i18n pattern (`Simcard::getMenuName()`).

| Element | Copy |
|---------|------|
| Primary CTA | The tile itself is the CTA — no separate button. Title (en_GB, source string): **"SIM Viewer"** → existing translation (pl_PL, `locales/pl_PL.po:12-13`): **"Podgląd SIM"**. Reuse `Simcard::getMenuName()` verbatim — do not introduce a second translatable string for the tile title. |
| Tile description (en_GB) | **"Coworkers' business phone numbers"** — new translatable string, source string TBD exact wording at implementation; must be short (single line, fits GLPI tile card without wrapping to more than ~2 lines at default width) |
| Tile description (pl_PL) | **"Służbowe numery telefonów współpracowników"** — locked by CONTEXT.md (2026-07-21 discussion) |
| Empty state heading | Not applicable to this phase — the tile has no empty state (it is a static navigational link, not a data list). The destination page's empty state ("No SIM cards are visible to you." / "Brak kart SIM widocznych dla Ciebie.") already exists from v1.0 and is out of scope for Phase 1 |
| Empty state body | Not applicable — see above |
| Error state | Not applicable to this phase — no new error path is introduced. The destination page's existing error copy ("The phone number field could not be located...") is unchanged, out of scope |
| Destructive confirmation | Not applicable — this phase performs no destructive user-facing action. Plugin *uninstall* removes the tile server-side (per CONTEXT.md), but that is an admin/CLI operation with GLPI's own uninstall confirmation flow, not a UI element this spec governs |

## UI Considerations

> Populated by the ui-phase UI-consideration probe (Step 9.5) and lifted by plan-phase's
> `## UI Considerations` lift rule via the identical rule as SPEC `## Edge Coverage`. Shape-rooted UI *state*
> coverage (empty / loading / error / populated / partial / overflow / zero-one-many / long-text).
> Empty-state and error-state COPY live in `## Copywriting Contract` above — this section covers
> state coverage and REFERENCES those rows rather than restating the copy (de-dup).

Applicable state considerations resolved: 2 covered, 1 backstop, 0 unresolved. Most of the standard state taxonomy (empty/loading/error/partial/overflow/zero-one-many) does not apply — the tile is a single static, non-data-driven navigational element, not a list or form.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| long-text | tile title + description | ✅ covered | Copy is fixed, short, and locked in this contract (title reuses `Simcard::getMenuName()`; description is a short single-sentence string in both locales) — no dynamic/user-supplied content can overflow the tile card |
| access-control visibility | tile presence on `/Helpdesk` | ✅ covered | Per CONTEXT.md, the tile is registered for all profiles with the helpdesk (simplified) interface via the same `addRightByInterface(..., 'helpdesk')` pattern used for the v1.0 READ right — users without the plugin's READ right or outside the helpdesk interface must not see the tile. This mirrors the existing `Simcard::canView()` + interface check already proven in `setup.php:90-92` for the menu entry |
| overflow / target-unreachable | tile click-through target (`front/simcard.php`) | 🧪 backstop | If the destination page 404s/403s (e.g. right revoked between page load and click), GLPI core's standard error handling applies — no plugin-specific error UI is introduced by this phase. Verify at UAT: clicking the tile as a right-holder lands on the existing SIM catalog page with no console/network errors |
